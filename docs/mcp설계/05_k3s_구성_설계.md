# k3s 구성 설계 (POC)

## 전체 구조

```mermaid
graph TD
    VM["VM (Linux)\n4코어 / 8GB RAM / SSD 100GB + NAS"]
    VM --> k3s["k3s 싱글노드"]
    k3s --> Traefik["Traefik (Ingress)\nk3s 기본 내장"]
    k3s --> Admin["관리자 페이지 Pod"]

    MCP -->|"API 호출"| GCal["구글 캘린더"]
    MCP -->|"API 호출 (2단계)"| GitLab["GitLab"]
    MCP -->|"API 호출 (2단계)"| Jenkins["Jenkins"]
```

---

## Pod 구성

| Pod | 역할 |
|-----|------|
| 관리자 페이지 | 사용자 로그인, 서비스 토큰 등록 UI |
| DB (postgres) | 사용자 정보, 서비스 토큰 저장 |
| MCP 서버 | JWT 확인 → DB에서 토큰 꺼냄 → 외부 API 호출 |
| Traefik | k3s 내장, 외부 요청 라우팅 (따로 관리 불필요) |

## 요청 흐름

### 최초 연동 (관리자 페이지)

```mermaid
sequenceDiagram
    participant U as 사용자
    participant A as 관리자 페이지
    participant DB as postgres

    U->>A: 회원가입 / 로그인
    A-->>U: JWT 발급
    U->>A: JWT + 서비스 API 키 등록 (노션, Slack 등)
    A->>DB: 사용자 - 서비스 토큰 저장
```

### 실제 MCP 요청

```mermaid
sequenceDiagram
    participant L as LLM
    participant T as Traefik
    participant M as mcp-server
    participant DB as postgres
    participant S as 외부 서비스 API

    L->>T: 요청
    T->>M: 라우팅
    M->>M: JWT 확인
    M->>DB: 해당 사용자 서비스 토큰 조회
    M->>S: API 호출 (노션 / Slack / 구글 캘린더)
    S-->>M: 결과 반환
    L-->>L: 결과 해석 후 작업 수행 (CRUD 등)
```

---

## 역할 분리

| 주체 | 역할 |
|------|------|
| MCP 서버 | API 연결 도구 제공 |
| LLM | 판단 + 실제 작업 수행 (CRUD 등) |

실제 작업(생성/수정/삭제)은 LLM이 판단해서 수행 — MCP 서버는 API 연결만 담당

---

## Kubernetes 리소스

| 리소스 | 용도 |
|--------|------|
| Deployment | 관리자 페이지, mcp-server, postgres |
| Service | 내부 통신용 ClusterIP |
| Ingress | 외부 접근 (Traefik) |
| Secret | API 키 (노션, Slack, 구글 캘린더) |
| ConfigMap | 서버 설정값 |
| PersistentVolumeClaim | postgres 데이터 저장 (SSD) |

## RAM 배분 (예상)

| 용도 | 사용량 |
|------|--------|
| OS/시스템 | ~1GB |
| k3s | ~512MB |
| 관리자 페이지 | ~512MB |
| mcp-server | ~1GB |
| postgres | ~512MB |
| 여유 | ~4.5GB |
