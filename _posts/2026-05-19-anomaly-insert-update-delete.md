- 이상(Anomaly)은 정규화가 부족할 때 발생하는 데이터 중복·불일치 문제야.
- 삽입 이상은 "원하지 않는 데이터까지 같이 넣어야 하는 문제".
- 갱신 이상은 "같은 데이터를 여러 곳 수정해야 해서 불일치 생기는 문제".
- 삭제 이상은 "하나 삭제했는데 필요한 정보까지 같이 사라지는 문제".
- 결국 핵심 원인은 중복 데이터와 잘못된 테이블 구조야.

## 예시: 한 테이블에 학생 \| 강의 \| 교수 몰려있을 때

| 학생 | 강의 | 교수 |
|---|---|---|
| 홍길동 | Java | 김교수 |
| 홍길동 | Python | 이교수 |
| (null) | Spring | ? |

**삽입 이상**
새 강의 추가하려는데 학생 정보 없으면 INSERT 못 함.

**갱신 이상**
교수 이름 바뀌면 여러 row 전부 수정해야 함.
하나라도 놓치면 데이터 불일치.

**삭제 이상**
학생 수강취소 row 삭제했는데 강의 정보까지 같이 사라짐.

## 해결: 정규화로 테이블 분리

```
학생 테이블  ←┐
강의 테이블  ←┤ 수강 테이블 (중간 테이블)
```

- 이상(Anomaly)은 "테이블을 왜 잘 나눠야 하는지" 설명하는 개념이야.
- 즉 정규화 필요성을 보여주는 대표적인 문제 사례들임.
- 데이터가 한 테이블에 너무 몰리면 중복과 불일치가 생겨.
- 그래서 엔티티 성격별로 테이블을 분리하는 거야.
- 결국 목표는 데이터 정합성과 유지보수성을 높이는 것.
