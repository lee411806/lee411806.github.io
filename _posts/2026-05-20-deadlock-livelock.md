## 1. 데드락 (Deadlock)

**정의:** 두 개 이상의 스레드가 서로가 가진 자원을 내놓으라고 버티며 그대로 얼어버린 상태

**스레드 상태:** Blocked 또는 Waiting (CPU 점유율 0%)

### 발생 조건 (4가지 — 하나라도 깨지면 발생 안 함)

1. **상호 배제 (Mutual Exclusion)** — 자원은 한 번에 한 스레드만 쓸 수 있음
2. **점유 및 대기 (Hold and Wait)** — 자원을 하나 쥔 채로 남의 자원을 기다림
3. **비선점 (No Preemption)** — 남이 가진 자원을 강제로 뺏을 수 없음
4. **순환 대기 (Circular Wait)** — 스레드들이 서로의 자원을 원하며 원형으로 꼬리를 물고 대기

### 해결 방법

- **자원 순서 할당** — 모든 스레드가 번호 순서대로 자원 획득 → 순환 대기 차단
- **타임아웃 설정** — 일정 시간 동안 자원을 못 얻으면 포기하고 물러나게 함

## 2. 라이브락 (Livelock)

**정의:** 데드락을 피하려고 서로 양보하거나 회피하다가 무한 루프에 빠져, 바쁘게 움직이지만 정작 아무것도 못 하는 상태

**스레드 상태:** Runnable 또는 Running (CPU 점유율이 100%까지 치솟을 수 있음)

### 핵심 조건 (3가지)

1. **자율적 회피 로직** — 충돌을 감지하면 스스로 자원을 내려놓고 비켜주는 코드가 있음
2. **동기화된 반응 시간** — 두 스레드가 칼군무처럼 똑같은 타이밍에 동시에 움직임
3. **결정론적 복구 알고리즘** — 우회하는 규칙이 고정되어 있어 항상 똑같은 패턴으로 반응함

### 해결 방법

- **랜덤 백오프 (Random Backoff)** — 재시도 대기 시간을 랜덤(예: 스레드A 10ms, 스레드B 45ms)으로 주어 타이밍을 강제로 어긋나게 만듦

---

## 3. 데드락 vs 라이브락 비교

| | 데드락 | 라이브락 |
|---|---|---|
| 스레드 상태 | Blocked / Waiting | Runnable / Running |
| CPU 점유율 | 0% | 최대 100% |
| 겉보기 | 완전히 멈춤 | 바쁘게 움직임 |
| 원인 | 서로 자원을 기다림 | 서로 양보하다 루프 |
| 해결 | 자원 순서, 타임아웃 | 랜덤 백오프 |

---

## 4. 동시성과의 연관성

- **자원 공유** — 멀티 스레드가 한정된 자원을 동시에 공유하려다 발생
- **비결정론적 실행** — 스레드가 ms 단위로 언제 실행될지 예측 불가
- **Lock의 역설** — 데이터가 깨지는 걸 막으려고 Lock을 채우다 DeadLock, Lock을 피하려 tryLock을 쓰다 LiveLock

> 데드락과 라이브락은 동시성 제어 도구(Lock)의 역설적인 부작용이다
