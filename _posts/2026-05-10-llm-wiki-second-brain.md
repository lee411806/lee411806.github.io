## 개요

LLM Wiki를 **Second Brain**과 **Project Wiki** 두 가지로 구축한다.

---

## 1. Second Brain (개인 지식 위키)

### 구조

- Obsidian(마크다운 로컬 노트) → 노트끼리 링크 연결 → **Graphify**로 그래프 시각화
- 임베딩 → 의미 추론 (그래프 + 벡터 → 온톨로지처럼 활용)

### Goodnight 스킬

- 실행 시 Slack, Wiki, Jira에 있는 모든 내용을 가져와서 임베딩
- 사용자가 말했던 모든 내용을 최신화 → 문서화 적용
- 출근 후 질문하면 전날 대화 내용 바탕으로 우선순위 파악
- 긴가민가했던 내용을 문서 찾지 않고 빠르게 확인 가능

### Graphify

- 클로드에서 `graphify.` 입력 후 엔터 → 그래프 생성
- 업데이트될 때마다 Graphify 실행 필요
- Obsidian과 연결 필수

> RAG 시스템은 동기화가 되어있지만, LLM Wiki는 동기화가 어려워 RAG를 완전히 대체하기는 어렵다.

---

## 2. Project Wiki (프로젝트 임베딩)

### 핵심 개념

- 프로젝트를 임베딩 → LLM Wiki화
- 프로젝트 분석/정보 탐색 시 **토큰 사용량 절감 + 속도 향상**
- 기본 프로젝트 기반 질문 → grep 대신 의미 검색으로 연관 클래스 추출

> 검색 20~30% vs 임베딩 검색 1% (토큰 기준)

### 전임자 머릿속 임베딩

- 신규 입사자가 전임자에게 물어보던 인사이트 → 임베딩 데이터로 대체
- 전임자 머릿속 → 데이터화 → 프로젝트 분석 시 공수 산정 및 역량 파악 가능

### 임베딩 스킬 구성

- MCP로 외부 데이터 가져와서 커맨드처럼 동작하게 구성
- 오늘 날짜 기준으로 최신화하는 스킬 별도 구성

---

## 적용 방향

| 상황 | 활용 위키 |
|---|---|
| 개발할 때 | Project Wiki (프로젝트 임베딩) |
| 리딩/공부할 때 | Second Brain 우선 |

---

## 기술 스택 요약

- **Obsidian** — 마크다운 로컬 노트, 노트 간 링크 연결
- **Graphify** — 그래프 + 벡터 기반 의미 추론
- **Embedding** — 프로젝트/문서 의미 검색
- **MCP** — 외부 소스(Slack, Jira, Wiki) 연동
- **GitHub** — 위키 소스 저장 및 동기화
