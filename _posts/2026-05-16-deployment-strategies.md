### 블루그린 배포 (Blue-Green Deployment)

핵심: **한 번에 전체 전환**

- 기존 운영 환경(Blue) + 새 버전 환경(Green) 동시 운영
- Green에 새 버전 미리 띄우고 검증 후, 트래픽만 Blue → Green 전환
- 문제 발생 시 트래픽을 Blue로 돌리면 빠른 롤백 가능
- 장점: 무중단 배포, 롤백 빠름, 운영 안정성
- 단점: 서버 자원 2배 필요, DB 스키마 변경 시 주의 필요

```
[Blue] A(v1) B(v1) C(v1)  ← 기존 운영
[Green] D(v2) E(v2) F(v2)  ← 새로 구성
         ↓ 트래픽 전환
사용자 → Green
```

---

### 카나리 배포 (Canary Deployment)

핵심: **일부 사용자에게만 점진 전환**

- 새 버전을 소수 사용자에게만 먼저 배포해 검증
- 5% → 30% → 100% 식으로 점진 확대
- 위험도는 가장 낮지만, 운영 복잡도는 가장 높음

---

### 롤링 배포 (Rolling Deployment)

핵심: **기존 서버를 하나씩 순서대로 교체**

```
처음:   A(v1) B(v1) C(v1)
중간:   A(v2) B(v1) C(v1)
그다음: A(v2) B(v2) C(v1)
완료:   A(v2) B(v2) C(v2)
```

- 추가 서버 없이 기존 서버 자체를 업데이트
- 자원 효율적이지만, 배포 중 v1/v2가 동시에 뜰 수 있음

---

### 비교 요약

| | 블루그린 | 카나리 | 롤링 |
|---|---|---|---|
| 전환 방식 | 전체 한번에 | 점진 | 하나씩 |
| 롤백 속도 | 빠름 | 빠름 | 느림 |
| 자원 | 2배 필요 | 중간 | 최소 |
| 위험도 | 낮음 | 가장 낮음 | 중간 |

> 비유: 롤링 = **기존 집 리모델링**, 블루그린 = **새 집 짓고 이사**
