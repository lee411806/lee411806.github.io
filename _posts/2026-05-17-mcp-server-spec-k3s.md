### 쿠버네티스 선택: k3s

싱글 VM 환경에서 MCP 서버를 운영하기 위해 쿠버네티스 배포판을 선택해야 했다.

**풀 k8s vs k3s RAM 비교**

k3s 사용 시:

| 용도 | 사용량 |
|------|--------|
| OS/시스템 | ~1GB |
| k3s 서버 | ~512MB |
| MCP 워크로드 | ~6GB (여유) |

풀 Kubernetes 사용 시:

| 용도 | 사용량 |
|------|--------|
| OS/시스템 | ~1GB |
| k8s 컨트롤 플레인 (etcd, API서버 등) | ~2-3GB |
| MCP 워크로드 | ~4-5GB (빠듯함) |

MCP 워크로드는 실제 서비스 연동(DB, API 등)을 처리하는 영역이므로 여유가 클수록 안정적이다.

### k3s vs minikube

| | k3s | minikube |
|---|---|---|
| 목적 | 경량 프로덕션 | 로컬 개발/테스트 |
| 사용 환경 | 실제 서버 | 개발자 노트북 |
| 포트폴리오 가치 | 높음 | 낮음 |

VM 서버 환경이므로 **k3s 선택**

---

### k3s 선택 이유 (면접 관점)

- 풀 k8s는 멀티노드 클러스터에서 진가를 발휘하도록 설계된 범용 오케스트레이터
- 싱글노드에서는 컨트롤 플레인 오버헤드만 크고 멀티노드 이점을 살릴 수 없음
- k3s는 싱글노드/온프레미스 환경에 최적화되어 동일한 기능을 더 적은 리소스로 제공
- CNCF 공식 인증 배포판으로 풀 k8s와 동일한 API 사용 가능

### 디스크 역할 분리

| 디스크 | 용도 |
|--------|------|
| SSD 100GB | k3s 설치, 컨테이너 이미지, 로컬 볼륨 |

### 현재 구성

- 싱글 노드 POC 구성
- 오케스트레이션 기능 활용 (Pod, Deployment, Service, ConfigMap 등)
- HA/멀티노드는 지원 안 되나 POC 목적으로 충분
