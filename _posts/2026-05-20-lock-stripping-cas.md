## 프레임부터 잡기

```
본질 (WHY)
└── 동시성 환경에서 성능을 높이자
    └── 방법 (HOW) = "Lock을 최소화하는 핵심 기술"
        ├── Lock Stripping  → 잠금 범위 최소화
        └── CAS             → 잠금 자체 제거 (Lock-Free)
            └── 결과 (RESULT) = 데드락 위험 감소/제거
```

> **Lock 최소화** = 목적이자 본질
> **데드락 해결** = 그 기술의 부산물

"데드락을 해결하려고 쓰는 게 아니라, 성능을 위해 Lock을 줄였더니 데드락도 자연스럽게 해결된다"

---

## 1. 분할 잠금 (Lock Stripping) — Lock을 최소화

### 기존 방식 — 통짜 자물쇠

```
Map 전체에 자물쇠 하나
────────────────────────────────
│  A방  │  B방  │  C방  │  D방 │
────────────────────────────────
         🔒 전체 잠금

스레드1: A방 씀 → 전체 잠금
스레드2: D방 쓰고 싶은데... 전혀 관계없는데도 대기 🚫
스레드3: B방 쓰고 싶은데... 똑같이 대기 🚫
```

### Lock Stripping — 방마다 자물쇠 따로

```
────────────────────────────────────────
│  A방🔒 │  B방🔓 │  C방🔓 │  D방🔓  │
────────────────────────────────────────

스레드1: A방 씀 → A방만 잠금 🔒
스레드2: D방 씀 → D방만 잠금 🔒  ← 동시에 가능!
스레드3: B방 씀 → B방만 잠금 🔒  ← 동시에 가능!
```

서로 다른 방이면 동시에 들어갈 수 있음. 같은 방일 때만 대기.

**실생활 비유**

> 기존: 도서관 전체를 한 명이 쓰는 동안 출입구를 잠가버림
>
> Lock Stripping: 구역별로 나눠서, 1구역 쓰는 사람이 있어도 2·3·4구역은 자유롭게 출입

## 2. CAS (Compare-And-Swap) — Lock을 제거

### 기존 Lock 방식

```
스레드A: "내가 쓸 동안 문 잠근다 🔒"
스레드B: (문 앞에서 멍하니 대기...)
스레드A: "다 썼다. 잠금 해제 🔓"
스레드B: "이제 들어간다"
```

### CAS 방식 — 낙관적 전략

```
1. 현재 메모리 값을 읽는다     → 값 = 10
2. 새 값을 계산한다            → 10 + 1 = 11
3. 쓰기 직전에 CPU한테 물어봄:
   "아직도 메모리가 10이야?"

   YES → 11로 바꿔! (원자적으로 즉시 실행)
   NO  → 누군가 바꿨네. 처음부터 다시.
```

"지금 내가 알고 있는 값이랑 실제 값이 같으면 바꾸고, 다르면 포기하고 재시도" — 이게 전부.

### 왜 데드락이 없나?

데드락은 스레드가 자원을 쥔 채로 다른 자원을 기다릴 때 발생.
CAS는 아무것도 안 쥐고, 값이 같으면 교체 / 다르면 재시도만 함.

```
아무도 잠그지 않음 → 아무도 기다리지 않음 → 데드락 불가능
```

### 왜 원자적(Atomic)이냐?

CPU 명령어(`CMPXCHG`) 하나로 비교 + 교체가 한 번에 실행됨.
비교하고 → 교체하는 사이에 다른 스레드가 끼어들 틈이 없음.
OS나 JVM이 아닌 **CPU 하드웨어 레벨**에서 보장.

**실생활 비유**

> 티켓 예매 마지막 좌석 1개, 두 명이 동시에 결제 누름
>
> CAS: "결제 시도할 때 아직 1개면 → 0으로 바꾸고 성공 / 이미 0이면 → 실패, 품절 안내"
>
> Lock 방식: "A가 결제하는 동안 사이트 전체 잠금 → B는 로딩 중..."

## 3. 두 기술 비교

| | Lock Stripping | CAS |
|---|---|---|
| 방식 | 잠금은 하되 범위를 최소화 | 잠금 자체가 없음 |
| 충돌 시 | 해당 버킷만 잠깐 대기 | 재시도 |
| 적합한 상황 | 쓰기 충돌이 잦을 때 | 충돌이 드물 때 |
| 데드락 가능성 | 낮음 | 없음 |

---

## 4. ConcurrentHashMap = 두 기술의 대표 예시

```
빈 버킷에 첫 데이터 넣기   → CAS (잠금 없이 빠르게)
이미 데이터 있는 버킷 수정 → Lock Stripping (해당 버킷만 잠금)
```

상황에 따라 더 빠른 걸 골라 씀 → 고성능 동시성 Map
