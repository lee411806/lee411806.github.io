### MCP 서버 역할 (내가 만드는 것)

- 각 서비스 API 키로 연동
- 도구(tool) 제공 — "일정 추가", "일정 조회", "젠킨스 빌드 실행" 등

### LLM 역할

- 사용자 요청 이해
- 어떤 도구를 언제 쓸지 판단
- MCP 서버의 도구 호출

---

### 핵심

MCP 서버는 **도구를 제공**, LLM은 **도구를 사용**

- 연동 로직 → MCP 서버
- 판단 → LLM

---

### 연동 대상 및 필요 키

| 서비스 | 필요한 것 |
|--------|-----------|
| 젠킨스 | Jenkins API 토큰 |
| 노션 | Notion API 키 |
| 구글 캘린더 | Google OAuth 키 |

---

### MCP 서버의 한계

**MCP 서버도 결국 API 통신이다.**

```
앱이 API 제공 O → MCP tool 만들 수 있음
앱이 API 제공 X → MCP tool 만들 수 없음
```

MCP 서버가 마법처럼 앱에 접근하는 게 아니라, 각 앱이 열어준 API를 호출하는 구조다.

**설계 순서:**
1. 연동할 서비스가 API를 열어줬는지 확인
2. 어떤 기능까지 API로 제공하는지 파악
3. 그 범위 안에서 MCP 도구 설계

개발서버의 경우 인프라팀에 어떤 API 엔드포인트를 열어줄 수 있는지 먼저 확인 필요.
